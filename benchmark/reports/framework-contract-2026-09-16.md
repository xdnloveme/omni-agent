## 已发现并处理的问题

- Docker CLI 插件和虚拟机目录共享是宿主前置条件。使用任务专用 Docker 配置；入口新增真实只读挂载检查。未共享目录已验证在 Harbor 启动前失败。
- 明确作答与评分两个镜像的 amd64 平台；健康检查准备普通用户日志权限，Oracle 与 Omni 共享同一环境契约。
- 修正免费补丁夹具生成脚本的 heredoc 缩进，并检查两种提交格式生成脚本的语法。
- 启动器原来的 subprocess.run 在中断时提前结束 Harbor。改为独立进程会话、单次转发取消并等待原生恢复，最多 150 秒。
- 同时终止包装进程与主进程会重复转发 TERM。适配器先记录主进程身份；公共停止能力先终止主进程，再清理该 UID 的残留进程。真实取消已验证原生 Trace 完整。

早期挂载失败、夹具失败及取消失败记录均保留，不计为成功验收。首次取消故障的容器曾需显式清理，恢复证据单独归档；最终版本已自动清理。

## 架构清理复核

用户要求进一步清理后发现，上轮“旧入口已移除”的结论只覆盖适配器目录，不够完整：旧 smoke/isolation-probe 任务、历史运行配置和部分重复准备逻辑仍存在。本轮已补齐清理：

- 删除旧 smoke 与 isolation-probe 可执行任务；免费模型服务迁入 execution-contract，Omni 配置迁入 adapters/omni/fixtures，没有兼容路径。
- 删除 swe-single、swe-single-isolated、swe-two 历史配置；当前三题/难题配置改为待重新准备的明确目录，不再引用 v7 产物。移除配置中被入口覆盖的 setup 超时和 jobs_dir，作答预算仍只有一个来源。
- SWE 准备器必须显式传入任务、数据集和固定镜像，删除默认 Axios 题。task.toml 仅在准备完成时写入一次。评分安装模板改为 Dockerfile.fragment，删除实际被跳过的默认 Axios FROM 行，镜像只取任务声明。
- Compose 平台和 init 只由公共环境写入；移除任务包、夹具的重复写入和评分模板中的重复 Compose 文件。夹具仅包含各自使用的收集器及补丁应用脚本。
- 网络诊断不再依赖旧任务目录、固定供应商或固定容器名称：显式指定准备好的任务、域名、新证据目录。它仍是 Harbor 边界测试，不承担正式运行、提交或评分。
